# iOS 持久聊天与前台自动同步

本分支基于 v1.1.7，为配套的 VCPMobile 持久任务网关构建个人自签包。主应用及分享扩展的 bundle ID、版本、签名要求保持上游值；覆盖安装时必须沿用原 Apple 账户和 Sideloadly 应用标识设置。不能先卸载旧应用。

## 行为

- 请求正文先写入手机 SQLite 的 `mobile_job_outbox`，每次模型请求使用新的 UUID。
- 网关确认接收后，Windows 进程独立连接 VCP 后端，边生成边保存响应；手机关闭连接不会取消该任务。
- 手机保留前台时读取增量；锁屏后是否还能即时收到内容由 iOS 决定。重新打开应用时按原任务编号读取，冷启动从字节 0 重建权威快照，再由原聊天事务提交终态。
- 提交应答丢失时先查询任务。只有明确不存在，才使用同一编号和同一已保存正文重试提交。网关按编号和正文哈希去重。
- 显式“停止”持久保存停止意图，向网关取消该任务。删除会话留下清理意图，不能让已删除的会话被恢复。
- 只有聊天记录事务已提交或用户已删除记录，才确认清理远端缓存。客户端解码、网络故障不授权清理结果。
- 打开/回到前台以及回复落盘会触发自动同步；合并连续触发，每两次自动尝试至少间隔 60 秒。活动生成先补齐，然后复用原同步会话。失败保留待同步意图，后台暂停后回前台重试。手动同步入口仍可用。
- 不增加后台音频、定位、推送或永久保活权限。
- 新消息与同步共用准入锁。发送消息前先停止并排空当前同步的写入，活动生成标记提交后释放锁；同步开始前在同一锁内确认没有活动生成。

这保证的是已完整送达电脑的一次模型请求，包括该请求由 VCP 后端执行的工具处理。上传尚未完成就失去网络时，手机保存的发送意图需要回到前台才能补送。群聊/JEV 中尚未由手机提交的后续轮次不属于已交接任务，手机端编排仍受系统暂停影响。

电脑必须保持开机、网络及 VCP 后端正常。网关或电脑重启会把正在执行的任务记为 interrupted，保留已有部分内容，不自动重跑可能已经产生外部副作用的工具。现有 VCP 后端超时仍然生效。

## 网关协议 v1

所有端点使用同一聊天 Bearer key；网关地址由当前聊天 URL 的同源 `/v1/mobile/jobs` 得到，不把聊天正文送到其他来源。

| 方法与路径 | 语义 |
| --- | --- |
| GET `/v1/mobile/jobs/capabilities` | 协议版本与能力 |
| POST `/v1/mobile/jobs` | `{requestId,route,body}`；body.requestId 必须相同；持久接收后返回 202 |
| GET `/v1/mobile/jobs/:id` | 当前状态、结果长度 |
| GET `/v1/mobile/jobs/:id/bytes?offset=N&limit=65536` | 最长 20 秒等待；JSON 中 data 为精确字节的 base64，带 offset、nextOffset、length、state、id |
| POST `/v1/mobile/jobs/:id/cancel` | 显式停止；未知 ID 写入取消墓碑，阻止迟到提交 |
| POST `/v1/mobile/jobs/:id/ack` | 仅终态可清理；保留编号/哈希墓碑，阻止重复执行 |

状态为 queued、running、cancelling、completed、failed、cancelled、interrupted、expired。网络错误不是服务端终态。SSE 必须正确结束且没有应用错误，不能仅凭 HTTP 200 或 EOF 判断成功。

配套 Windows 网关默认限制：4 个活动任务，单请求 16 MiB，单结果 64 MiB，总结果 512 MiB，最多 10,000 个任务索引。未确认结果不会自动删除；额度耗尽时拒绝新任务，不能通过删除去重索引来自动腾空间。网关数据是私有运行数据，不能提交 GitHub。

## 维护与验证

- SQLite 迁移：0106；不改变现有跨设备消息协议。
- 安装前先完成手机到电脑的手动同步并备份电脑聊天数据。旧版的迁移器不认识 0106，升级后不能把“直接覆盖旧版 IPA”当作数据库回退方案；禁用功能的回退包仍须保留该迁移，或使用升级前的完整应用数据备份恢复。
- 后续升级官方版本前，也必须先合并本分支并处理迁移历史；上游未来自己的 0106 可能与本分支编号冲突。续签使用已验收并保存的定制 IPA。
- Rust 入口：`infra/vcp_client/durable_transport.rs`、`persistence/mobile_job_repository.rs`、`sync/auto_sync.rs`。
- 本地检查：`pnpm check`、`pnpm check:ios`、`cargo test --locked --lib`。
- Windows 网关另有真实 HTTP 断线、丢失应答、取消竞态、磁盘故障和原同步传输回归测试。
- macOS 使用原 `iOS Device Archive` 工作流，release 配置，产物为 unsigned IPA。检查 manifest 中主应用和扩展都是 arm64 / IOS，记录提交 SHA 与 IPA SHA-256。
- 安装后验证：发送一条回复较长的消息，确认电脑已接收，锁屏等待，再回应用检查完整回复与自动同步；另外测试手动停止、网络恢复、冷启动恢复和原手动同步。

源码检查、Windows host 测试、iOS 归档编译和真实 iPhone 验证是不同证据，不能互相替代。本文件描述分支设计，不表示某台手机已经安装或验收。
